AVL-JTAG Driver
===============

.. inheritance-diagram:: avl_jtag._driver
    :parts: 1

The :doc:`avl_jtag.Driver </modules/avl_jtag._driver>` does not implement the JTAG protocol. Instead, during the run phase it:

1. Pulses TRSTn (if present)
2. Opens a ``remote_bitbang`` server socket and launches OpenOCD configured to connect to it
3. Services the bitbang requests generated by OpenOCD ``init`` (scan chain examination)
4. Connects to the OpenOCD Tcl RPC port
5. For each sequence item, sends the command and services bitbang requests until the result is returned

OpenOCD Process Lifetime
------------------------

OpenOCD is never left running once a test finishes, however it finishes:

- **Sequence completes** - the agent sends ``shutdown`` over Tcl RPC and waits for OpenOCD to exit.
- **Sequence fails or the test is cancelled** (assertion, Tcl error, simulation timeout) - the agent / driver terminate OpenOCD (SIGTERM, then SIGKILL after 1 s).
- **OpenOCD hangs** - the driver raises ``TimeoutError`` after ``timeout`` seconds without bitbang activity and terminates it.
- **Python exits** - any remaining instances are terminated by an ``atexit`` handler.
- **Simulator dies** (crash, ``$fatal``, SIGKILL) - on Linux OpenOCD is launched with ``PR_SET_PDEATHSIG`` so the kernel kills it with its parent.

See :ref:`protocol` for the bitbang request mapping and :ref:`configuration` for the driver variables.
